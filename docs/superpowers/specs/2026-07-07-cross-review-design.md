# Claude ↔ antigravity(Gemini) 相互レビュープロトコル 設計

- 日付: 2026-07-07
- ステータス: 承認済み
- スコープ: **Medoの開発ワークフロー**(steering/workflow.md)への相互レビュー組み込み
- スコープ外: Medoプロダクト自体の生成物(要件・アーキ案・スライド)へのマルチモデルレビュー組み込み。差別化軸「自律的multi-agentはやらない」との整合確認が必要なため、別サイクルで正本スペックの改訂として扱う

---

## 1. 目的

開発の各フェーズの中間生成物(スペック・実装計画・実装diff)を最小単位で相互レビューし、
上流での見落としの早期検出と実装品質の底上げを図る。レビューが際限なくループしないよう、
試行回数・終了条件・裁定ルールをあらかじめ固定する。

## 2. 原則

1. **作ったモデル ≠ レビューするモデル**(自己レビューを相互レビューと呼ばない)
2. **Claudeが常に最終裁定者**。レビュアーの指摘も無検証で採用しない(superpowers:receiving-code-review の姿勢を踏襲)
3. コードは**レビューOKだけでは終わらない**。`uv run pytest` + `uv run ruff check .` のパスを終了の必要条件に含める
4. レビューコストを管理する: 上限2ラウンドで打ち止め、好みレベルの指摘はラウンドを消費しない

## 3. レビューマトリクス

| 生成物 | 作成者 | レビュアー | レビュー手段 |
|---|---|---|---|
| スペック(`docs/superpowers/specs/`) | Claude | agy(Gemini) | `antigravity:delegate` で観点指定レビュー(設計原則との整合・見落とし・曖昧さ) |
| 実装計画(`docs/superpowers/plans/`) | Claude | agy(Gemini) | 同上(Taskの抜け・依存関係・テスト戦略) |
| 実装Taskのdiff | agy / Codex | Claude | Claude自身がdiffレビューし、pytest/ruffを自分の環境で実行して検証 |
| Claudeが直接書いたコード | Claude | agy(Gemini) | `antigravity:review`(現diffのクロスモデルレビュー) |

## 4. ラウンドと終了条件

- 1つの生成物に対するループは **最大2ラウンド**(レビュー→修正→再レビューで打ち止め)
- **早期終了条件**(以下を両方満たしたら上限前でも終了):
  1. 重大指摘(欠陥・設計原則違反・要件との不整合)がゼロ
  2. コードの場合は `uv run pytest` と `uv run ruff check .` がパス
- **上限到達時**: 未解決事項を列挙し、Claudeが採否を裁定して確定する
- **エスカレーション**: 設計原則(product.md)に関わる対立、スコープ拡大、課金が発生する変更はユーザーに確認する
- **好みレベルの指摘**(命名の趣味・スタイルの揺れ等)はラウンドを消費せず、Claude裁定で即確定する

## 5. 記録

- コミット本文に1行で残す。形式: `review: <レビュアー> <ラウンド数>R / 重大<n>件解消 / 未解決<n>`
  - 例: `review: agy 2R / 重大2件解消 / 未解決0`
- 実装計画のTaskチェックボックスの完了条件にレビュー完了を含める
- 専用のレビューログファイルは作らない(個人開発では過剰なため。監査が必要になったら再検討)

## 7. 決定の経緯(brainstormingでの合意)

- レビュー単位: 中間生成物すべて(スペック / 計画 / Task diff)
- 試行回数: 最大2ラウンド
- 終了条件: 重大指摘ゼロ + テスト/リントパスの併用
- 運用形態: 軽量記録付きプロトコル(レビューログファイル型・記録なし型は不採用)
- 対象: まず開発ワークフロー。プロダクト側は後続サイクル
