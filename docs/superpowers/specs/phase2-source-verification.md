# 出典検証の強化(フェーズ2・並行)

ステータス: 実装済み(#147 core / #148 cli + skills)

`facts save` が受け取った出典URLを実際に取得し、LLMが転記した数値が出典本文に書かれているかをコードで確かめる設計。原則1「発想は自由、事実は縛る」の、**出典からの初回転記**という唯一LLMが数値に触れる箇所を塞ぐ。

親: [medo-phase2-design.md](medo-phase2-design.md)(実装順序の「並行」項目)

---

## 1. なぜ要るか

現状の `Fact` の検証は `source` が**URLの形をしているか**だけである(`core/src/medo_core/facts.py`)。次のどれも検出できない:

- 存在しないURL、または別の資料を指すURL
- 出典には `3.2兆円` とあるのに `--value 32 --unit 兆円` と転記した(桁・単位の取り違え)
- 出典に無い数値を、もっともらしい出典URLと組にして保存した

product.md は「LLMが数値に触れるのは出典からの初回転記のみ(出典に忠実・無加工)」と定めるが、**その忠実さを確かめる仕組みが無い**。以降の数値はfermi・CLIが決定論で扱うため、ここで入った誤りはそのまま提案の根拠になる。

---

## 2. 方式の選択

| 案 | 内容 | 判断 |
|---|---|---|
| **A(採用)** | 原文抜粋 `--quote` を必須にし、「抜粋が本文にある」「抜粋中に数値がある」を決定論で照合 | 偶然一致を防ぎ、根拠を位置ごと残せる。判定は決定論のまま |
| B | 抜粋なしで本文全体から数値を探す | 長いページでは同じ数値が別の文脈に現れて偶然一致する。根拠の位置が残らない |
| C | 本文と主張の支持関係をLLMで判定(RefChecker型) | 原則1(数値・事実の通り道にLLMを挟まない)に反する |

Aの決定論照合が保証するのは「**その数値が出典の抜粋に書かれている**」ことまでで、「年・地域・指標が主張と対応している」ことは保証しない(抜粋に `2024年3.2兆円、2025年3.3兆円` とあれば、「2025年は3.2兆円」という誤った主張も数値照合は通る)。この対応関係は決定論で判定できないため、Jev(TypeSafe System One)の**補助の分類**で疑わしいものを浮かせる。拒否の判断には入れない(§5)。

## 3. データ形式と挙動

### 3.1 対象

`kind` が `market` / `policy` / `trend` のファクト(URL出典が必須のkind)。`company` はヒアリング等の由来表記で取得先が無いため対象外(`verification.status` は `not-applicable`)。

### 3.2 `facts save` の入力

| オプション | 内容 |
|---|---|
| `--quote "<原文抜粋>"` | 出典本文から写した原文抜粋。**対象kindでは必須**。`value` がある場合は、その数値を含む最小の一文(表なら単位の見出しを含む行)にする。`value` の無い定性ファクトでも、抜粋が本文にあることは確かめる |
| `--unverifiable-reason "<理由>"` | 本文は取れたが検証できない場合の明示的な逃げ道(例: PDF抽出の文字化け)。取得・照合をせず未検証として保存し理由を残す |

黙って検証を飛ばす経路は作らない。

### 3.3 判定

| 状況 | 結果 |
|---|---|
| 抜粋が本文にあり、`value` があれば抜粋中に一致する数値がある(§4) | `verified` で保存 |
| 取得できない(HTTPエラー・タイムアウト・本文が空=JS描画等・非対応の Content-Type) | `unverified`(`reason: "fetch-failed: <詳細>"`)で保存 |
| 本文は取れたが、抜粋が見つからない / 抜粋中に一致する数値が無い | **拒否**(下記のエラー形式) |
| `--unverifiable-reason` を指定 | `unverified`(`reason: "declared: <理由>"`)で保存 |

取得不能を拒否にしないのは、行政PDFや403で調査が止まるのを避けるため。その代わり §3.5 の出力に未検証として現れ、Skillは引用時の注記を義務とする。

**拒否時のエラー**は、Agentが同じ呼び出しを繰り返さずに次の行動を選べるよう、原因の候補と次の手を示す:

```
error: 抜粋が出典本文に見つかりません(本文 12,345 文字を取得)
  本文中の近い箇所: 「…市場規模は3.2兆円(2024年)と…」
  次の手: (1) 抜粋を本文どおりに写し直す
          (2) 出典の数値自体が違う → 転記を見直す
          (3) 抽出テキストの文字化け・欠落が疑われ、目視で出典に書かれていると確認できた
              → --unverifiable-reason "抽出不良: <状況>" を付けて再実行
```

「近い箇所」は抜粋の先頭数文字の一致位置、無ければ主張値の数値文字列の一致位置の前後を示す。

### 3.4 `Fact` のフィールド追加

```python
class Verification(BaseModel):
    status: Literal["verified", "unverified", "not-applicable", "legacy"]
    reason: str = ""          # unverified のときのみ
    checked: str = ""         # ISO日付。legacy は空
    support: Literal["supported", "doubtful", "unjudged"] = "unjudged"

class Fact(BaseModel):
    ...
    quote: str = ""
    verification: Verification | None = None
```

- **`legacy` は読み込み時にだけ付く**。保存済みJSONに `verification` が無い場合、`FactStore.get` / `list` は対象kindなら `legacy`、`company` なら `not-applicable` として返す。移行は不要
- **`FactStore.save` は `verification` が `None` のファクトを拒否する**。検証を経ない新規保存が `legacy` に紛れ込むのを、CLIではなくcoreで防ぐ(CLI以外の経路=webapp等も同じ規則に従う)
- `legacy` を保存し直すことはできない(`save` は `status="legacy"` を拒否する)
- **kindごとに許す状態を制約する**: 対象kindは `verified` / `unverified`、`company` は `not-applicable` のみ(`Fact` のバリデータで検査)
- **`verified` を作るのは core の `verify_fact(fact, body)` だけ**とする(照合して `Verification` を付けたファクトを返す)。`save` は照合を経たかを証明できないため、これは呼び出し側の契約であり、CLI以外の経路(webapp等)も `verify_fact` を通す
- 対象kindで `quote` が空のまま `verified` にはできない(`Fact` のバリデータで検査)

### 3.5 見える場所

未検証の数値が気づかれずに提案の根拠になる経路を、出力ごとに塞ぐ。

| 出力 | 追加 |
|---|---|
| `facts list --format json` | 各要素に `verification` |
| `facts list`(digest) | `[UNVERIFIED]` / `[LEGACY]` / `[DOUBTFUL]`(`[STALE]` と並べる) |
| `fermi calc` | `FermiResult` に `unverified_facts`(参照したファクトのうち `unverified` / `legacy` のID。`not-applicable` は検証対象外であって未検証ではないので含めない)と `doubtful_facts`(`verified` だが `support=doubtful` のID)を足し、生成物の `content` に残す。いずれか1件以上なら標準出力に警告行を出す |
| `status`(`facts` セクション) | `unverified` / `legacy` 件数。要件未作成時の固定ゼロ件(`status.py`)にも同じキーを足す |
| Skill | 未検証・legacy・doubtful のファクト、およびそれを参照したfermi結果を引用するときは提案文中に注記する(原則4のstale注記と同じ扱い)。対象は `medo-investigate` / `medo-propose-options` / `medo-grow-prfaq`(fermi結果を再引用するため) |

`legacy` は検証機能の導入前に保存されたことを示すだけで、失敗を意味しない。ただし数値が確かめられていない点は `unverified` と同じなので、fermi・Skillでは同じく注記対象とする。`supported` は表示しない(「事実確認済み」と誤読されるため。§5)。

## 4. 数値照合の規則

照合はcoreの純関数で行う(ネットワークに触れない)。

### 4.1 正規化

1. 抜粋と本文の両方にNFKC正規化をかける(全角数字・全角記号・全角カンマを半角へ)
2. **抜粋の包含判定**だけは、さらに空白・改行をすべて除いた文字列で行う(日本語PDFの抽出は改行・空白が混ざりやすい)。部分一致で判定し、あいまい一致は使わない
3. **数値の読み取り**はNFKC後・空白保持の抜粋に対して行う。空白・改行は数値の境界として扱う(`2024  3.2` を `20243.2` と読まない)

### 4.2 抜粋中の数値の読み取り

- 数値 = 符号 + 数字列(桁区切り `,` と小数点を含む)。符号は `-` / `−` / `▲` / `△` / `マイナス` を負として読む
- 数字列の直後の倍率語を倍率として読む: 千=10³ / 万=10⁴ / 百万=10⁶ / 億=10⁸ / 兆=10¹²
- `3兆2,000億` のように倍率語が降順に連続するときは合算する
- 数値(と倍率語)の直後に続く文字列を**後続文字列**として持つ(`3.2兆円程度` なら `円程度`)
- `約` / `およそ` / `程度` などの概数表現は数値の値を変えない。概数であることは抜粋に残っており、転記の忠実さの問題ではないため

### 4.3 主張値との一致

**丸めは許さない**。出典からの転記は忠実・無加工が原則(product.md 原則1)であり、丸め・換算はfermiの仕事である。

- 主張値 = `value` × `unit` の倍率語。主張の基底単位 = `unit` から倍率語と末尾の括弧書き1つ(注記)を除いた残り。除くと空になるなら除かない(`兆円` → `円`、`%` → `%`、`%(F1向上率)` → `%`)。注記は保存時の説明で出典の表記には現れないため
- 抜粋中の数値が次をすべて満たせば一致:
  1. **倍率を掛けた値が、符号を含めて主張値と等しい**(浮動小数の誤差のみ許容。相対誤差 1e-9)。表記の変換(`3,215,000百万円` ↔ `3.215兆円`)は情報を失わないので許すが、`3.2兆円` ↔ `3.215兆円` は許さない
  2. 主張に基底単位があるとき、後続文字列が**主張の基底単位で始まる**(前方一致。`円程度` / `%増` / `円(前年度比)` は `円` / `%` と一致)
- **倍率語も後続の単位も無い数字**(表中の `3,215,000` など)は、**抜粋中の単位宣言(`単位:X` / `単位：X`)がちょうど1つで、その X が主張の `unit`(末尾の括弧書きの注記を除いたもの)と等しい場合に限り**、主張の単位で書かれた値として照合する。このとき条件1は `value` との比較になり、条件2(後続文字列の前方一致)は単位宣言の一致で代える。単位宣言が無い・2つ以上ある場合は、どの表・列の単位か決まらないので照合しない
- 抜粋中の数値のどれか1つが一致すれば合格(年・指標との対応は§5の補助判定に委ねる)

| 抜粋 | 主張 | 結果 |
|---|---|---|
| `市場規模は3.2兆円` | 3.2 兆円 | 一致 |
| `3,215,000百万円` | 3.215 兆円 | 一致(表記の変換のみ) |
| `3,215,000百万円` | 3.2 兆円 | **不一致**(丸め) |
| `3兆2,000億円` | 3.2 兆円 | 一致 |
| `市場規模は3.3兆円` | 3.2 兆円 | 不一致 |
| `3.2兆円` | 32 兆円 | 不一致(桁の取り違え) |
| `約3.2兆円程度` | 3.2 兆円 | 一致(後続文字列 `円程度` は `円` で始まる) |
| `前年比12.5%増` | 12.5 % | 一致 |
| `▲5.2%` | -5.2 % | 一致 |
| `▲5.2%` | 5.2 % | 不一致(符号) |
| `3.2兆人` | 3.2 兆円 | 不一致(基底単位) |
| `(単位:百万円)3,215,000` | 3215000 百万円 | 一致(単位宣言が1つで `百万円`) |
| `(単位:万人)3,215,000` | 3215000 百万円 | 不一致(単位宣言が `万人`) |
| `(単位:万人)3,215,000 (単位:百万円)42` | 3215000 百万円 | 不一致(単位宣言が2つ) |
| `2024  3.2`(表の行、単位見出し無し) | 3.2 兆円 | 不一致(単位宣言が無い) |

### 4.4 v1でやらないこと

- **換算の突合**(ドル→円、年率→月率)と**丸め**。いずれもfermiの仕事(原則1)
- **漢数字**(三兆二千億)。出典の数値表記の大半はアラビア数字。必要になってから足す
- **`ポイント` と `%` の区別**の特別扱い。基底単位の前方一致で `%` と `ポイント` は別物として扱われる(`12.5ポイント` は `%` と一致しない)ので、追加規則は要らない

## 5. Jevの補助判定(`support`)

§2の通り、数値照合は「年・地域・指標が主張と対応しているか」を保証しない。この対応関係をJevの `noul` 質問で判定し、`support` に記録する。

- `supported` / `doubtful` / `unjudged` の3値。**拒否には使わない** — 判定は確率的であり、保存可否を決定論から外さないため
- `doubtful` は `facts save` の出力に警告として出し、§3.5 の通り表示する。`supported` は表示しない(「事実確認済み」と誤読されるため)
- `verified` のときだけ判定する(未検証なら照合の前提が無い)
- `TYPESAFE_API_KEY` が無い、またはJev呼び出しが失敗・タイムアウト(10秒)した場合は `unjudged`。保存は妨げず、失敗は警告として出力する
- 数値そのものはJevに判定させない。数値一致は§4の決定論照合だけが決める
- アダプタは既存の `cli/src/medo_cli/jev.py` に関数を足す

レビューでは「v1から外す」案が出た(同期の外部呼び出しで `facts save` が遅くなる、`supported` が誤解を招く)。採らなかった理由: 上記の年・指標の取り違えは決定論照合の構造的な穴で、補助判定が無いと `verified` の過信を招く。遅延はタイムアウトと `unjudged` への退避で上限を切り、誤解は `supported` を表示しないことで避ける。

## 6. 配置と依存

| 層 | 内容 |
|---|---|
| core `facts.py` | `Verification`・`Fact` のフィールド追加、`FactStore.save` の検査、読み込み時の `legacy` 付与 |
| core `source_check.py`(新規) | 正規化・数値読み取り・一致判定・抜粋照合・近い箇所の抽出の純関数 |
| core `fermi.py` | `FermiResult.unverified_facts` |
| core `status.py` | `facts` の `unverified` / `legacy` 件数 |
| cli `fetch.py`(新規) | 取得(標準 `urllib`、タイムアウト付き、リダイレクト追従)と本文抽出。HTMLは `trafilatura`(Apache-2.0。バイト列を渡し、文字コード判定は `Content-Type` / `meta charset` に従わせる — Shift_JIS の官公庁サイト対策)、PDFは `pypdf`(BSD) |
| cli `main.py` | `facts save` の判定の組み立てとエラー形式、`list` / `fermi calc` の表示 |

- 依存はcliに足す。coreは依存を増やさない(ネットワークとパーサはアダプタ側、structure.md の依存方向に従う)
- `pymupdf` は抽出品質は高いが **AGPL** のため公開リポジトリの依存にしない
- 取得関数は注入可能にし、テストはネットワークに出ない

## 7. 実装の分割

| # | 内容 | 影響範囲 |
|---|---|---|
| A | `source_check.py` の照合規則と `verify_fact`、`Fact` / `FactStore` の変更(legacy読み込み・kind別状態・save検査)、`fermi` の `unverified_facts` / `doubtful_facts` と `fermi calc` の警告行、`facts list` の `verification` と digest表示、`status` の件数 | core + cli(表示のみ) |
| B | 取得・抽出アダプタ、`facts save` の `--quote` / `--unverifiable-reason` と判定・エラー形式、Jevの `support` **+** `medo-investigate` / `medo-propose-options` / `medo-grow-prfaq` の `--quote` の付け方と注記義務 | cli + skills。**`facts save` の入力が変わる = Skill契約に影響(人間レビュー対象)** |

Aから順に。Aは `facts save` の**入力**を変えない。Aの間、CLIは対象kindを暫定 `unverified(reason: "pre-verification-cli")`、`company` を `not-applicable` で保存する — 未検証である事実をそのまま表示・警告に出すので、AとBの間の版でも未検証値が気づかれずに計算へ流れることはない。**Bは `facts save` の入力とSkillを同じPRで変える** — `--quote` が必須になった時点で既存Skillの保存コマンドが失敗するため、分けると間の版で契約が壊れる。

## 8. テスト方針

- §4.3 の表をそのままテーブル駆動のユニットテストにする(core)
- `FactStore.save` が `verification=None` と `status="legacy"` を拒否すること、`verification` の無い既存JSONが `legacy` として読めること
- `fermi` が `unverified` / `legacy` の参照を `unverified_facts` に、`doubtful` を `doubtful_facts` に入れ、`not-applicable` はどちらにも入れないこと
- kind別の許可状態(バリデータが拒否する組み合わせ)と、`verify_fact` が照合結果どおりの `Verification` を付けること
- 取得は関数注入で偽物に差し替える(HTML本文 / Shift_JIS のHTML / PDF / HTTPエラー / 空本文)。ネットワークに出ない
- 拒否時のエラーに「近い箇所」と `--unverifiable-reason` の案内が含まれること
- Jevは既存テストと同じく `urlopen` をモンキーパッチする。`TYPESAFE_API_KEY` 無し・タイムアウトで `unjudged` になること

## 9. やらないこと

- 取得できない場合の拒否(調査が止まるため。§3.3)
- JS描画ページのヘッドレスブラウザ取得(依存が重い。`fetch-failed` で未検証に落とす)
- 既存ファクトの一括再検証コマンド(必要になってから `facts verify` として足す)
- 取得本文のキャッシュ・保存(出典の再配布にあたり得る。抜粋のみ保存する)
- fermiでの未検証参照の拒否(未検証でも桁感の把握には使える。注記で足りる)
