# 出典検証の強化(フェーズ2・並行)

ステータス: 未承認(実装着手前)

`facts save` が受け取った出典URLを実際に取得し、LLMが転記した数値が出典本文に書かれているかをコードで確かめる設計。原則1「発想は自由、事実は縛る」の、**出典からの初回転記**という唯一LLMが数値に触れる箇所を塞ぐ。

親: [medo-phase2-design.md](medo-phase2-design.md)(実装順序の「並行」項目)

---

## 1. なぜ要るか

現状の `Fact` の検証は `source` が**URLの形をしているか**だけである(`core/src/medo_core/facts.py`)。次のどれも検出できない:

- 存在しないURL、または別の資料を指すURL
- 出典には `3.2兆円` とあるのに `--value 32 --unit 兆円` と転記した(桁・単位の取り違え)
- 出典に無い数値を、もっともらしい出典URLと組にして保存した

product.md は「LLMが数値に触れるのは出典からの初回転記のみ(出典に忠実・無加工)」と定めるが、**その忠実さを確かめる仕組みが無い**。以降の数値はfermi・CLIが決定論で扱うため、ここで入った誤りはそのまま提案の根拠になる。

---

## 2. 方式の選択

| 案 | 内容 | 判断 |
|---|---|---|
| **A(採用)** | 原文抜粋 `--quote` を必須にし、「抜粋が本文にある」「抜粋中に数値がある」を決定論で照合 | 偶然一致を防ぎ、根拠を位置ごと残せる。判定は決定論のまま |
| B | 抜粋なしで本文全体から数値を探す | 長いページでは同じ数値が別の文脈に現れて偶然一致する。根拠の位置が残らない |
| C | 本文と主張の支持関係をLLMで判定(RefChecker型) | 原則1(数値・事実の通り道にLLMを挟まない)に反する |

Jev(TypeSafe System One)は**補助の分類**にだけ使い、拒否の判断に入れない(§5)。

---

## 3. データ形式と挙動

### 3.1 対象

`kind` が `market` / `policy` / `trend` のファクト(URL出典が必須のkind)。`company` はヒアリング等の由来表記で取得先が無いため対象外。

### 3.2 `facts save` の入力

| オプション | 内容 |
|---|---|
| `--quote "<原文抜粋>"` | 出典本文から写した原文抜粋。**対象kindでは必須**。`value` の無い定性ファクトでも、抜粋が本文にあることは確かめる |
| `--unverifiable-reason "<理由>"` | 本文は取れたが検証できない場合の明示的な逃げ道(例: PDF抽出の文字化け)。未検証として保存し理由を残す |

黙って検証を飛ばす経路は作らない。

### 3.3 判定

| 状況 | 結果 |
|---|---|
| 抜粋が本文にあり、`value` があれば抜粋中に一致する数値がある | `verified` で保存 |
| 取得できない(HTTPエラー・タイムアウト・本文が空=JS描画等・非対応の Content-Type) | `unverified`(`reason: "fetch-failed: <詳細>"`)で保存 |
| 本文は取れたが、抜粋が見つからない / 抜粋中に一致する数値が無い | **拒否**。非ゼロ終了し、`error:` に理由と本文中の近い箇所(抜粋先頭の一致位置の前後)を添える |
| `--unverifiable-reason` を指定 | 取得・照合をせず `unverified`(`reason: "declared: <理由>"`)で保存 |

取得不能を拒否にしないのは、行政PDFや403で調査が止まるのを避けるため。その代わり §3.5 の通り、未検証はstaleと同じく全レスポンスに付き、Skillは注記を義務とする。

### 3.4 `Fact` のフィールド追加

```python
class Verification(BaseModel):
    status: Literal["verified", "unverified", "legacy"]
    reason: str = ""          # unverified のときのみ
    checked: str = ""         # ISO日付。legacy は空
    support: Literal["supported", "doubtful", "unjudged"] = "unjudged"

class Fact(BaseModel):
    ...
    quote: str = ""
    verification: Verification = Verification(status="legacy")
```

- 既存データは `quote` / `verification` を持たない。読み込み時の既定値で `legacy` になり、**移行は不要**
- 対象kindで `quote` が空の新規保存はCLIが拒否する(モデル側では必須にしない — legacy読み込みを壊さないため)

### 3.5 見える場所

| 出力 | 追加 |
|---|---|
| `facts list --format json` | 各要素に `verification` |
| `facts list`(digest) | `[UNVERIFIED]` / `[DOUBTFUL]`(`[STALE]` と並べる) |
| `status` | `facts` に `unverified` 件数 |
| Skill | 未検証・doubtful のファクトを引用するときは提案文中に注記する(原則4のstale注記と同じ扱い) |

`legacy` は表示上 `unverified` と区別して `[LEGACY]` とする。検証機能の導入前に保存されたことを示すだけで、失敗を意味しない。

## 4. 数値照合の規則

照合はcoreの純関数で行う(ネットワークに触れない)。

### 4.1 正規化

抜粋と本文の両方に同じ処理をかける:

1. NFKC正規化(全角数字・全角記号・全角カンマを半角へ)
2. 空白・改行をすべて除く(日本語PDFの抽出は改行・空白が混ざりやすい)
3. 抜粋の包含は正規化後の**部分一致**。あいまい一致は使わない

### 4.2 抜粋中の数値の読み取り

- 数字列(桁区切り `,` と小数点を含む)の直後の倍率語を倍率として読む: 千=10³ / 万=10⁴ / 百万=10⁶ / 億=10⁸ / 兆=10¹²
- `3兆2,000億` のように倍率語が降順に連続するときは合算する
- 倍率語の後に続く非数字の語(`円` / `人` / `台` / `%` 等)を**基底単位**として読む
- 倍率語が無い数字は、(a) そのままの値 と (b) 主張の単位で書かれた値 の両方として照合する(表の数値を出典の単位のまま転記した場合を拾う)

### 4.3 主張値との一致

- 主張値 = `value` × `unit` の倍率語。例: `--value 3.2 --unit 兆円` → 3.2×10¹²、基底単位 `円`
- 許容幅: **精度の粗い側の最下位桁の半分**。`3.2兆` の許容区間は [3.15兆, 3.25兆)
- 抜粋の数値に基底単位が付いていれば、主張の基底単位と一致しなければならない。付いていなければ比較しない
- 抜粋中の数値のどれか1つが一致すれば合格

| 抜粋 | 主張 | 結果 |
|---|---|---|
| `市場規模は3.2兆円` | 3.2 兆円 | 一致 |
| `3,215,000百万円` | 3.2 兆円 | 一致(3.215兆は区間内) |
| `3兆2,000億円` | 3.2 兆円 | 一致 |
| `市場規模は3.3兆円` | 3.2 兆円 | 不一致 |
| `3.2兆円` | 32 兆円 | 不一致(桁の取り違え) |
| `12.5%` | 12.5 % | 一致 |
| `3.2兆人` | 3.2 兆円 | 不一致(基底単位) |
| `(単位:百万円)3,215,000` | 3215000 百万円 | 一致(倍率語の無い数字を主張の単位で読む) |

### 4.4 v1でやらないこと

- **換算の突合**(ドル→円、年率→月率)。換算はfermiの仕事(原則1)
- **漢数字**(三兆二千億)。出典の数値表記の大半はアラビア数字。必要になってから足す
- **抜粋の外の単位表記**(表見出しの「(単位:百万円)」)。Skillが抜粋に含めるよう指示する

---

## 5. Jevの補助判定(`support`)

抜粋が `statement` を支えているか(年・地域・指標が一致しているか)をJevの `noul` 質問で判定し、`support` に記録する。

- `supported` / `doubtful` / `unjudged` の3値。**拒否には使わない** — 判定は確率的であり、保存可否を決定論から外さないため
- `doubtful` は `facts save` の出力に警告として出し、§3.5 の通り表示する
- `TYPESAFE_API_KEY` が無い、またはJev呼び出しが失敗した場合は `unjudged`(保存は妨げない。失敗は警告として出力する)
- 数値そのものはJevに判定させない。数値一致は§4の決定論照合だけが決める
- アダプタは既存の `cli/src/medo_cli/jev.py` に関数を足す

## 6. 配置と依存

| 層 | 内容 |
|---|---|
| core `facts.py` | `Verification`・`Fact` のフィールド追加 |
| core `source_check.py`(新規) | 正規化・数値読み取り・区間照合・抜粋照合の純関数。判定結果を返す |
| cli `fetch.py`(新規) | 取得(標準 `urllib`、タイムアウト付き)と本文抽出。HTMLは `trafilatura`(Apache-2.0)、PDFは `pypdf`(BSD) |
| cli `main.py` | `facts save` の判定の組み立て、`list` / `status` の表示 |

- 依存はcliに足す。coreは依存を増やさない(ネットワークとパーサはアダプタ側、structure.md の依存方向に従う)
- `pymupdf` は抽出品質は高いが **AGPL** のため公開リポジトリの依存にしない
- 取得関数は注入可能にし、テストはネットワークに出ない

## 7. 実装の分割

| # | 内容 | 影響範囲 |
|---|---|---|
| A | `source_check.py` の照合規則と `Fact` のフィールド追加(後方互換読み取り) | core |
| B | 取得・抽出アダプタ、`facts save` の判定、Jevの `support`、`list` / `status` 表示 | cli。**`facts save` の入力と出力が変わる = Skill契約に影響(人間レビュー対象)** |
| C | `medo-investigate` / `medo-propose-options` の `--quote` の付け方と、未検証・doubtful の注記義務 | skills |

Aから順に。BはAの照合関数を使い、CはBのCLI契約を前提にする。

---

## 8. テスト方針

- §4.3 の表をそのままテーブル駆動のユニットテストにする(core)
- 取得は関数注入で偽物に差し替える(HTML本文 / PDF / HTTPエラー / 空本文)。ネットワークに出ない
- Jevは既存テストと同じく `urlopen` をモンキーパッチする。`TYPESAFE_API_KEY` 無しで `unjudged` になることを確かめる
- legacy読み込み: `quote` / `verification` の無い既存JSONが読めることを確かめる

---

## 9. やらないこと

- 取得できない場合の拒否(調査が止まるため。§3.3)
- JS描画ページのヘッドレスブラウザ取得(依存が重い。`fetch-failed` で未検証に落とす)
- 既存ファクトの一括再検証コマンド(必要になってから `facts verify` として足す)
- 取得本文のキャッシュ・保存(出典の再配布にあたり得る。抜粋のみ保存する)
